# Auth0 baseline conservation bootstrap proposal

This local backport starts from pristine `8ec5927059b294bab9e42e9818e011ea6b300738`. It adds the approved digest-only conservation implementation from `e7508dfbc33f74ff22b80ed87f9bbb4e26a56c04` to the existing Auth0 seller Worker. No deployment, activation, provider/configuration edit, customer operation, credential or access grant is authorized by this document or performed by this patch.

An actual offline Wrangler 4.76.0 dry-run of the pristine committed baseline produced `entry.js`, exactly 100,392 bytes with SHA-256 `07afb5fb8fdf5847d874a5e9336c6695fa0d9b4506672d28929a5e90e00038dc`. This exactly matches the named version `51bc4dda-fe57-4e28-8a56-22313b19dbb9` main module hash and length independently obtained by root. The build used the committed production config, `--env-file /dev/null`, a stripped environment, task-local Wrangler metadata/log paths, and OS denial of all network and credential-store reads. This binds local baseline code bytes to that recorded named module; it does not independently verify deployment activity, actual resource bindings, secrets or customer conservation.

The baseline source lacks a complete private business-store and whole-MEDIA capture route. A later Clerk candidate capture cannot establish what existed before the candidate. A separately authorized preparation version would make this read capability available while preserving Auth0, before a prospective candidate run. Only an actual complete capture under independently pinned deployed source, resource bindings and account authority can establish that run's original selectors. Deploying a preparation version is itself a source change: a capture taken afterward cannot retroactively prove that preparation preserved every predeployment byte or that an earlier baseline was complete. Historical Staff listing projections and referenced images remain narrower evidence.

## Minimal runtime change

`GET /api/aircraft-sale/admin/accounts/_conservation/capture` (or the equivalent internal `/admin/accounts/_conservation/capture`) branches on the existing SellerStore queue before `loadState`, rollback, normal success/error persistence or audit. Every page uses the unchanged `assertAccountOrigin` and separately scoped `accountAdministrator(request, false)` checks. Listing-reviewer, security-operator and seller authority do not substitute for the account administrator. Existing account-origin/audience/allowlist bindings must already be correct; this patch adds none.

The constructor's existing `CREATE TABLE IF NOT EXISTS seller_records` statement moves, unchanged, to the first ordinary `loadState`. This is necessary so constructing an instance for a capture cannot create storage. Missing schema fails capture without DDL; ordinary request, private mail and alarm paths still initialize before loading and retain their existing business/persistence behavior. The default state, Auth0 methods/PKCE/callback/session/security logic and normal `route` remain unchanged. The reply helper accepts optional headers only to report `Allow: GET` for a rejected capture method.

The conservation module is byte-identical to the approved source (SHA-256 `aa1058f887fd22948af86bee950152fdd7b00a3acffbcaaeace8bf607db29070`). It performs SQL schema introspection/SELECT and an unfiltered native `storage.list({limit: 1})` emptiness check, plus whole-bucket R2 list/conditional GET/HEAD. It never creates tables, saves state, audits, schedules alarms, delivers mail, or writes/deletes bucket objects. Native `_cf_KV` metadata is the sole permitted extra table, and only if the native KV API returns an empty Map; user `__cf_kv`, other tables/views, nonempty/unavailable KV, extra columns, unknown bucket names and malformed values fail closed.

## Scope and protocol

Every full JSON business row in `profiles`, `identities`, `listings`, `drafts`, `files` and `idempotency` is hashed, retaining private fields, file ownership and future fields. No status, owner or listing selector filters the scope. All currently listed objects in the bound `MEDIA` bucket are enumerated through every provider cursor, including orphan, deleting-reference and zero-byte objects. Full streamed bytes, supported metadata, versions, ranges and checksums are checked and hashed. Every file catalogue reference must exist. Raw customer values, keys, subjects, metadata and media bytes are never returned.

Success returns the unchanged schema-1 `RWAS_SELLER_CONSERVATION_PAGE` protocol: scope/counts/lengths/time, opaque IDs/cursors and SHA-256 digests. Start, record pages (100 rows maximum), one-object media pages and a separate terminal page are required. Cursors are actor-bound, one-use, in memory, expire after 10 minutes and are lost on restart. Rejected origin/auth does not consume another valid cursor; once validated work consumes a cursor, failure or uncertain delivery requires a fresh capture. Consumers must verify complete consistent sequences, counts and roots, not infer completeness from HTTP 200. Independent source/resource/tool-delivery pins remain necessary; self-reported schema/algorithm digests are protocol markers.

Each continuation rehashes business rows; conditional GET and HEAD check each initial media version/metadata; terminal completion re-enumerates the entire inventory. This is observed stability, not a cross-store atomic transaction or proof against a separate writer that changes and restores data between observations. Existing hard limits are unchanged: 10,000 records and media objects, 2 MiB per record, 32 MiB total state, 512 MiB per object, 1 TiB declared whole-media bytes, 100 provider inventory pages, 4 captures, and 20 seconds of work per page. A larger/unsupported real scope remains a blocker requiring separate review.

Explicit exclusions are the thirteen existing mutable auth/security/receipt/delivery/audit namespaces: `identitySecurity`, `authTransactions`, `authEvents`, `auth0EventReceipts`, `securityOperations`, `accountAdminOperations`, `sessions`, `codes`, `mailRequests`, `mailSequences`, `rates`, `audit`, `outbox`. No assertion covers them. Nonempty separate Durable Object KV is rejected rather than silently omitted.

This patch covers only the seller-v2 Durable Object and its bound MEDIA bucket. It does not cover the separate legacy `SALEDATA` KV, `SALEBUCKET` R2, Cloudflare Images, other buckets/backends, R2 historical/removed objects or Pages' intake receipts. Those require separate source-bound complete readers and actual evidence; no legacy schema or private conservation is inferred from this capability.

## Offline verification

Use the existing installed dependency tree read-only through the ignored `node_modules` symlink. No install, dotenv/config read or provider credentials are needed. Run with pinned Node 22.22.0 and an environment containing only task-local TMPDIR and `/usr/bin:/bin` PATH:

```sh
node --test --test-concurrency=1 tests/aircraft-sale/conservation.test.mjs tests/aircraft-sale/identity.test.mjs tests/aircraft-sale/security.test.mjs tests/aircraft-sale/account-admin.test.mjs
node --test --test-concurrency=1 tests/aircraft-sale/conservation-runtime.test.mjs tests/aircraft-sale/runtime.test.mjs tests/aircraft-sale/account-admin-runtime.test.mjs
```

The reused unit fixtures cover complete full-field/privacy/record and provider pagination, actor/replay/expiry/capacity, references, stream lengths, metadata/version/races, cancellation, strict SQLite and native KV scope, and no-load/save/audit interception. Added cases prove construction plus failed methods/origin/authorization/provider payloads touch no SQL/KV/media/persistence and that every continuation independently reauthorizes before reads without transferring actor-bound cursors. Unchanged Auth0 identity, security and account-administrator suites check existing ownership, callback/replay, revocation, role and mutation behavior.

The reused actual local workerd fixture exercises real SQLite, R2 and DigestStream; rejects missing schema without DDL; then shows normal health still initializes. Independent Node digest oracles cover all six private business rows and referenced/orphan/zero-byte objects. Strict native KV/alias/table/column tests preserve unknown state and media; fresh capture after restarting the same persisted SQLite/R2 directories is digest-equal with zero normal loads/saves. The added restart check proves an old cursor is unavailable and its rejection does not mutate persisted state. All write/probe/seed routes and fictional authority exist only in test subclasses, never product code. Conservation fixture outbound service rejects external requests; other existing selected suites use synthetic provider/Access service fixtures.

Actual outcomes: 42/42 selected unit cases and 5/5 native cases passed, with zero failures, skips or cancellations. Native TAP retains the existing workerd unread-request stream warning (`expected clean; can't read more data after a previous read didn't complete`); passing assertions do not imply zero runtime diagnostics. The original reused fixture/ordinary request handling was left unchanged. TAP, source proof and the pristine bundle/log are retained separately in `.local-conservation-checks`. These offline tests establish implementation behavior, not live capture availability, production account authority, deployment approval or a completed conservation baseline.
