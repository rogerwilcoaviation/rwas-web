# Resumable migration framework and owner handoff

This is a locally implemented and tested framework, not an accepted live migration. The deployed legacy source/version/format and real source/destination storage are unverified. No denied resource read is retried, including through Jerry or another principal. There is no Cloudflare import endpoint, production adapter, provider grant or executable CLI apply option. No real export/resource was used for development or tests.

## Safe executable boundary

`node scripts/seller-migration.mjs EVIDENCE.json VERIFIED_INPUTS.json NEW_PLAN.json` validates only and produces a new exclusive mode0600 review artifact. Dry-run is the default, requires complete migration inputs, and never calls adapters. Existing output cannot be overwritten. Unsupported flags, including `--apply`, halt.

`prepareMigration(bundle, inputs)` returns a stable digest, explicit IDs/ownership, draft records, deterministic private object keys, counts, expected final hashes and quarantine list. `runMigration(..., {mode:'apply', adapters})` executes only with injected `kind:'synthetic-fixture'` adapters. The test adapter uses disposable filesystem-backed state and checkpoints. Merely labelling another adapter synthetic is not authorization to touch real data. No adapter capable of accessing Cloudflare is supplied.

The earlier `seller-legacy-dry-run.mjs` remains the broad offline planning/attestation check. The new framework additionally requires an explicitly reviewed **normalized-listings-v2** contract and rejects unknown fields, credential/session fields, unsafe object keys/names, filename/type mismatches, missing owner/destination mappings and baseline collisions. It does not decode an unknown deployed export or silently repair incompatible data. Archived/deleted/unknown source states require an explicit reviewed exclusion or transformation so retry cannot resurrect customer deletions. Known source draft/pending/active/paused/sold records all become private drafts with revision1 and no approval; source snapshot time is the new draft creation/update time under this declared transform.

## Required input packet

The evidence bundle is the strict `source`, `listings`, `objects`, `ownership` schema documented in [ROLLOUT.md](ROLLOUT.md). Source listing fields must be the destination field allowlist plus `id`, `sellerEmail`, `status`, `photos`, `videos`, `logbooks`. Each source association is `{key}` only. Object manifests are `{key,size,sha256,contentType}`. Unknown metadata requires a separately reviewed conversion/provenance map, not relaxation of checks. Private orphan objects remain in source backup and quarantine; they are not copied/deleted.

The second file has:

- `version:1`, stable safe `migrationId`.
- `review:{sourceFormat:'normalized-listings-v2',sourceSha256,verifiedBy,evidenceRef,verifiedAt}`. `sourceSha256` must match the identified source artifact. This is operator attestation; the framework cannot independently verify denied deployed code.
- `destination:{accountId,storeId,bucketName,private:true,isolated:true,receiptRetention:'append-only'}` identifying an isolated destination, plus `writeBoundary:{ref,verifiedBy,evidenceRef,verifiedAt}` for an established exclusive write boundary. Existing setup is not inferred from available credentials.
- `ownerMap:[{ownerEmail,ownerId,verifiedBy,evidenceRef,verifiedAt}]`, exactly covering independently attested owners with canonical email and existing destination UUID profile IDs. There is no profile creation, email-based takeover, session import or hold clearing. Two source emails cannot silently merge into one profile.
- `listingMap:[{sourceId,destinationId}]`, exactly covering source listings with unique destination UUIDs absent from the baseline. IDs never change on restart. Object keys derive deterministically from destination listing/category and source-key SHA256.
- `destinationBaseline:{listings:[...normalizedRecords],objects:[...objectMetadata]}` covering the entire chosen isolated destination import scope. Existing records are opaque immutable baseline values; live storage translation remains unimplemented. Object metadata requires safe `key`, positive integer `size`, SHA256 and MIME type.
- `backups:{source:{ref,verifiedBy,evidenceRef,verifiedAt,listingsSha256,objectsSha256,counts},destination:{...}}`, with distinct immutable private backup references. Each `counts` is `{listings,objects,bytes}` and each hash exactly covers its snapshot array. Source backup covers all objects, including quarantined orphans. Backup attestations alone are insufficient for apply: actual backup manifests and every backup object's bytes are reread and verified.

The tests construct complete packets using reserved `.test` owners and synthetic references. They are examples of the declared format, not evidence of actual RWAS source, ownership or provider readiness. Do not copy their resource names/proofs into production.

## Apply adapter contract for future review

A real adapter must first be implemented against verified source and destination schemas and reviewed separately; these method names describe a normalized domain port, not existing Worker routes or direct SQLite row format. The current engine refuses a production adapter. Required methods:

| `source.readObject(snapshotRef,key)`                    | Read immutable source bytes and actual content type without writing/deleting source. Return `{body:Uint8Array or async binary stream,contentType}`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `backup.snapshot(ref)`, `backup.readObject(ref,key)`    | Independently read the complete private backups and actual backed-up bytes, including source orphans and destination baseline objects.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

Prevent concurrent imports and ordinary seller writes. Preserve independent holds and provider security state.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `destination.readObject(key)`                           | Read actual destination bytes and MIME, not only metadata hash; null if absent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `destination.putObjectIfAbsent(metadata,bytes)`         | Private conditional create only, with exact owner/listing/category/migration metadata. Never overwrite another object. Existing conflicting values halt; returned/lost responses are reconciled by reading actual bytes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `destination.commitDraftIfAbsent(draft,receipt)`        | Atomically persist one draft, its file associations and its durable import receipt, or return matching existing record/receipt. Never overwrite existing/edited/deleted rows. A receipt without its record or a record without a matching receipt is a conflict, not permission to recreate/adopt it. Keep migration receipts permanently as append-only tombstones across normal listing/account purge, cleanup, import retry and restore. A lost commit response before checkpoint plus deletion of both record and receipt would otherwise be indistinguishable from a never-committed draft and could resurrect it. Production acceptance must prove receipt retention and all-writer lease behavior; merely returning a policy string is insufficient. |

Checkpoint plan/digest/membership/phase must match; no fresh checkpoint over conflicting history.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

`AtomicFileJournal` supplies mode0600 atomic rename checkpoints, fsyncs file and containing directory, and rejects stale revisions. It **depends on** the destination's exclusive lease; it is not a standalone cross-process lock. A real distributed destination needs an appropriate durable lease/transaction implementation, not the test mutex.

## Ordering, resumability and reconciliation

Before any destination mutation: validate full schema/ownership/source review/mappings/backups; inspect actual destination policy and pinned source snapshot; reread complete backup manifests and all backup bytes; verify destination owner identities and untouched baseline metadata/bytes; reject foreign destination writes or partial/missing draft receipts; validate every referenced source file's actual length, hash, extension and signature. Type signatures are not a malware scanner or full media decoder. Source reads are bounded by reviewed byte count; overflowing binary streams are cancelled by iterator unwinding.

Persist initial checkpoint, then copy objects with conditional create and immediate destination byte/hash verification. Checkpoint each copy. All copies stay private and unassociated with a public listing. Reread source bytes immediately before copying and halt on mutation after preflight. After all copies pass, commit drafts and receipts atomically, then checkpoint each listing. No publish/review approval, source deletion, account mutation or credential/session migration occurs.

Finally compare complete destination counts and canonical sorted listing/object hashes against baseline plus the planned import; reread all final bytes, including unchanged baseline objects. Only then save complete reconciliation. Hash/count consistency is scoped to the adapter's complete inventory; it is not proof the deployed adapter paginates or isolates correctly until separately verified.

Restart uses the same immutable input digest and IDs, rereads actual backups/destination bytes/receipts and reconciles completed writes whose response/checkpoint was lost. A successful repeat does not copy/commit again or rewrite the complete checkpoint. Conflicting input, changed baseline, corrupted bytes, foreign objects, missing committed records/receipts or missing receipted objects halt. The framework never recreates a deleted committed listing, republishes one, clears account holds or automatically deletes partial copies. Retain private staging objects and checkpoints for operator reconciliation; cleanup/rollback is a separate verified operation.
